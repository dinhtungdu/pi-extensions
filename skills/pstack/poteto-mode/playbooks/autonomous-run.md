# Autonomous run

Autonomy means continuing routine in-scope work without unnecessary questions. It does not widen authority.

1. Pin the done predicate, task checkout, constraints, checks, and actions that remain parent-only.
2. Use one writer at a time. Delegate bounded units with `subagent`; review and verify each before starting a dependent unit.
3. Continue through ordinary test failures, review corrections, and documented local setup problems.
4. Stop for product ambiguity, credentials, destructive uncertainty, changed external state, or publication/infrastructure authority not explicitly granted.
5. Keep a decision trail with `/skill:show-me-your-work` only when the run is long enough to need one.

Finish with verified artifacts, commands and results, remaining gaps, and any exact user decision. Never self-authorize push, PR mutation, merge, deploy, cleanup, or Manager lifecycle changes.
